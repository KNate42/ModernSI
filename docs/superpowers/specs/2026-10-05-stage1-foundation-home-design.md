# ModernSI — этап 1: фундамент и главная

Дата: 2026-10-05
Источник: ТЗ `~/Downloads/TR.docx`, интро-видео `~/Downloads/gemini_generated_video_081069f7.mp4`, два слайда из ТЗ («What is International Campus Hub?», «Student Ideas → Real Initiatives»).

## 1. Цель и рамки

ModernSI — независимая международная платформа для студентов: обмен опытом и знаниями, студенческие инициативы, форум. По духу она напоминает сеть международных микрокампусов, но **не использует ничего из бренда какого-либо университета**: ни названий, ни символики, ни цветовой палитры, ни фирменных шрифтов.

Проект готовится к **реальному запуску** с живыми пользователями. Публичный запуск возможен только после этапа 5. До этого всё работает локально или на закрытом стенде.

### Разбиение на этапы

| Этап | Содержание |
|---|---|
| **1 (этот документ)** | Каркас стека, авторизация по учебной почте, роли, интро, шапка, айдентика, главная с циклом «идея → событие», обзорные страницы разделов |
| 2 | Наполнение разделов: Academic (личный планировщик, курсы, ресурсы, отзывы о преподавателях), International (карточки кураторов: стипендии, обмены, конференции), Community, Personal (уведомления на сайте, история, достижения, портфолио) |
| 3 | Forum: международный форум, темы, ответы, модерация, жалобы |
| 4 | Чат на Cassandra |
| 5 | Прод: деплой на домен, SMTP-провайдер, бэкапы, мониторинг, админка |
| позже | Финансы и заказы (сейчас не нужны, таблицы не закладываем) |

### Вне рамок этапа 1

Форум, чат, финансы, уведомления на сайте, комментарии к идеям, загрузка файлов (кроме аватара), мобильное приложение, многоязычность интерфейса. Интерфейс только на английском.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Назначение | Реальный запуск |
| Доступ | Регистрация по учебной почте с доменом из списка, который ведёт админ. Гости читают, писать и голосовать могут только подтверждённые пользователи |
| Кампусы | Метка в профиле, определяется по домену почты. Пространство общее, без фильтрации по кампусам |
| Контент разделов (этап 2) | Кураторы публикуют официальные карточки, студенты добавляют курсы, ресурсы и отзывы. Расписание и дедлайны — личный планировщик |
| Архитектура | Модульный монолит FastAPI |
| Хранилища | PostgreSQL — ядро; Redis — сессии, коды, rate-limit; MongoDB — профили (на этапе 2 ещё каталог); ClickHouse — лента, логи, аналитика; Cassandra — чат (этап 4) |
| Акцент айдентики | Ultraviolet |
| Интро | ~6 секунд, один раз за сессию браузера |

## 3. Архитектура

### Репозиторий

```
modernsi/
  backend/    FastAPI, uv, SQLAlchemy 2 (async) + Alembic, pytest
  frontend/   Next.js (App Router, TypeScript), GSAP, Playwright
  infra/      docker-compose.yml (dev), docker-compose.test.yml (test)
  docs/       спецификации и планы
```

Сервисы в `infra/docker-compose.yml`: `postgres`, `redis`, `mongo`, `clickhouse`, `mailpit`. Бэкенд и фронтенд в разработке запускаются локально. Cassandra добавится на этапе 4.

### Модули бэкенда

Каждый модуль состоит из трёх слоёв:
- `router` — HTTP-слой;
- `service` — логика;
- `repository` — доступ к своему хранилищу.

Модуль обращается к другому модулю только через его `service` и никогда не читает чужие таблицы напрямую.

| Модуль | Ответственность | Хранилище |
|---|---|---|
| `core` | Конфиг (pydantic-settings из env), клиенты баз, ошибки, логирование, проверка Origin | — |
| `auth` | Регистрация, подтверждение почты, вход и выход, сброс пароля, роли, блокировки | Postgres, Redis |
| `campuses` | Разрешённые домены, заявки на добавление домена, домен → метка кампуса | Postgres |
| `profiles` | Био, аватар, языки, интересы, ссылки | MongoDB |
| `ideas` | Идеи, голоса, рассмотрение, команда, жалобы | Postgres |
| `events` | События хаба, «Я пойду» | Postgres |
| `feed` | Outbox → ClickHouse, лента активности, логи запросов, счётчики главной | Postgres (outbox), ClickHouse |
| `mail` | Отправка писем по SMTP, шаблоны писем | — |

### Поток данных в ClickHouse

Значимые действия записываются в таблицу `outbox` в той же транзакции Postgres, что и само действие:
- `user_verified`;
- `idea_created`;
- `idea_reached_review`;
- `idea_decided`;
- `team_formed`;
- `event_published`.

Воркер (отдельный процесс `modernsi worker`, тот же код) пачками переносит записи в ClickHouse. Перенесённые записи помечаются в outbox и удаляются через 7 дней. Если ClickHouse недоступен, воркер повторяет попытку с нарастающей паузой, и ничего не теряется.

Логи HTTP-запросов (метод, путь-шаблон, статус, длительность, анонимизированный user_id) пишутся в ClickHouse асинхронным буфером. Потеря логов при падении допустима.

### Фронтенд

- Next.js проксирует `/api/*` на FastAPI через rewrites. Cookie сессии остаётся first-party, CORS не нужен.
- Публичные страницы рендерятся на сервере: главная, список и карточка идеи, события, обзоры разделов.
- Формы и голосование — клиентские компоненты.

## 4. Авторизация и роли

### Данные (Postgres)

- `email_domains`: id, domain (unique, lower), campus_label, country_code, is_active, created_at.
- `domain_requests`: id, domain, university_name, requester_email, status (`pending|approved|rejected`), created_at.
- `users`: id (uuid), email (unique, lower), password_hash, display_name, email_domain_id → email_domains, role (`student|student_gov|curator|admin`), status (`pending|active|blocked`), created_at, verified_at.

### Регистрация и вход

1. `POST /api/auth/register` принимает email, password (не короче 10 символов) и display_name.
   - Если домена нет среди активных, сервер отвечает `422 domain_not_allowed`. Фронтенд в этом случае показывает форму заявки на домен (`POST /api/campuses/requests`). Когда админ одобрит домен, заявителю уходит письмо.
2. Создаётся пользователь со статусом `pending`, на почту уходит 6-значный код.
   - Код хранится в Redis `verify:<user_id>`: TTL 15 минут, не больше 5 попыток.
   - Повторная отправка — не чаще раза в 60 секунд.
3. `POST /api/auth/verify` переводит пользователя в `active` и пишет событие `user_verified` в outbox.
4. `POST /api/auth/login` и `POST /api/auth/logout`, `POST /api/auth/logout-all`, `GET /api/auth/me`.
5. Сброс пароля: `POST /api/auth/password/forgot` → код на почту → `POST /api/auth/password/reset`. После сброса все сессии пользователя закрываются.

### Сессии и защита

- Сессия — 32 случайных байта в base64url.
  - Ключи в Redis: `session:<sha256(token)>` → user_id, плюс множество `user_sessions:<user_id>` для выхода на всех устройствах.
  - Срок жизни 30 дней, продлевается при активности.
- Cookie `msi_session`: httpOnly, Secure (в проде), SameSite=Lax, Path=/.
- Пароли хешируются argon2id (`argon2-cffi`).
- Изменяющие запросы (POST/PUT/PATCH/DELETE) принимаются только с `Origin` из списка разрешённых в конфиге, иначе `403`.
- Rate-limit — фиксированное окно в Redis:

  | Действие | Лимит |
  |---|---|
  | регистрация | 5/час на IP |
  | вход | 10 за 15 минут на IP+email |
  | отправка кода | 1/60 с и 10/сутки |
  | голос | 60/мин на пользователя |
  | создание идеи | 5/сутки на пользователя |
- Почта никогда не отдаётся в публичных ответах API. Публично видны только display_name и campus_label.

### Роли

| Роль | Права на этапе 1 |
|---|---|
| `student` | Подать идею, голосовать, вступить в команду, «Я пойду», пожаловаться |
| `student_gov` | То же, плюс решение по идеям в статусе `in_review` |
| `curator` | То же, что у student, плюс создание событий напрямую (без идеи) и оформление события для любой идеи в `forming_team` |
| `admin` | Всё, плюс управление доменами, заявками на домены, ролями, блокировками, скрытие идей |

Первого админа создаёт CLI: `modernsi create-admin --email ... --name ...`. Пароль вводится интерактивно.

Админские операции на этапе 1 доступны через API и CLI. Админка в интерфейсе появится на этапе 5.

## 5. Идеи и события

### Данные (Postgres)

- `ideas`:
  - id, author_id, title (5–120 символов), summary (до 280), body_md (до 10 000);
  - category (`event|academic|club|research|volunteering|campus_life`);
  - scope (`campus|network`), campus_label (копия метки автора на момент создания);
  - status, vote_count, team_size, is_hidden, review_note;
  - created_at, updated_at, review_started_at, decided_at, expires_at.
- `idea_votes`: (idea_id, user_id) PK, created_at.
- `idea_team_members`: (idea_id, user_id) PK, joined_at.
- `idea_reports`: id, idea_id, reporter_id, reason (до 500), created_at, resolved_at.
- `events`:
  - id, idea_id (nullable), created_by, title, description_md;
  - starts_at, ends_at, location_text, online_url (nullable), campus_label (nullable = вся сеть);
  - going_count, created_at.
- `event_rsvps`: (event_id, user_id) PK.
- `outbox`: id, kind, payload jsonb, created_at, shipped_at.

### Жизненный цикл идеи

```
open ──(vote_count ≥ VOTE_THRESHOLD)──▶ in_review
open ──(expires_at прошёл, порог не набран)──▶ expired
in_review ──(student_gov)──▶ approved | rejected (review_note обязателен) | needs_changes (review_note обязателен)
needs_changes ──(автор правит и отправляет повторно)──▶ in_review (голоса сохраняются: порог уже набран)
approved ──(сразу)──▶ forming_team (автор — первый участник команды)
forming_team ──(team_size ≥ TEAM_MIN)──▶ можно оформить событие
forming_team ──(автор или куратор создаёт событие)──▶ live
live ──(ends_at события прошёл)──▶ done
```

**Параметры** задаются в конфиге. Значения по умолчанию:

| Параметр | По умолчанию |
|---|---|
| `VOTE_THRESHOLD` | 50 |
| `IDEA_TTL_DAYS` | 60 |
| `TEAM_MIN` | 3 |

**Голосование**
- Голосовать можно только за идею в статусе `open`.
- За свою идею голосовать нельзя.
- Голос можно отозвать, пока идея `open`.
- Вставка или удаление голоса и изменение `vote_count` делаются в одной транзакции с блокировкой строки идеи (`SELECT … FOR UPDATE`).
- Переход в `in_review` происходит в той же транзакции.

**Редактирование.** Автор может править идею только в статусах `open` (без смены категории) и `needs_changes`.

**Плановые переходы.** Переходы `expired` и `done` делает воркер раз в 10 минут.

**Пользователь** может вступить в команду, только пока идея `forming_team`, и выйти из неё, пока событие не создано. Автор выйти не может.

**Модерация**
- Жалоба доступна один раз на пользователя для каждой идеи.
- Админ может скрыть идею (`is_hidden`). Скрытая идея пропадает из списков и ленты, а по прямой ссылке отдаёт 404 всем, кроме автора и админа.

### API (основное)

| Метод и путь | Доступ |
|---|---|
| `GET /api/ideas?status=&category=&sort=trending\|new\|closest&cursor=` | все |
| `GET /api/ideas/{id}` | все |
| `POST /api/ideas`, `PATCH /api/ideas/{id}` | active (автор) |
| `POST/DELETE /api/ideas/{id}/vote` | active |
| `POST /api/ideas/{id}/decision` | student_gov, admin |
| `POST/DELETE /api/ideas/{id}/team` | active |
| `POST /api/ideas/{id}/report` | active |
| `GET /api/events?upcoming=1`, `GET /api/events/{id}` | все |
| `POST /api/events` | curator, admin, автор идеи в `forming_team` |
| `POST/DELETE /api/events/{id}/rsvp` | active |
| `GET /api/feed?cursor=` | все |
| `GET /api/stats` | все |
| `GET /api/campuses` | все |
| `GET/PUT /api/profiles/me`, `GET /api/profiles/{user_id}` | — |
| `/api/admin/*`: домены, заявки, роли, блокировки, скрытие | admin |

**Сортировки**
- `trending` — голоса за последние 7 дней.
- `closest` — `open`-идеи по убыванию `vote_count / VOTE_THRESHOLD`.

**Пагинация** курсорная.

### Почтовые уведомления этапа 1

- код подтверждения;
- код сброса пароля;
- домен одобрен;
- «твоя идея ушла на рассмотрение»;
- «решение по идее» (с review_note);
- «команда собрана, оформи событие»;
- «у идеи, в команде которой ты состоишь, появилось событие».

## 7. Интро

> Обновлено 2026-10-07: цвета интро изменены, см. раздел 8 документа `2026-10-07-visual-refresh-design.md`; хронометраж и поведение остаются в силе.

Покадровый разбор исходного видео (10 с, 1280×720, монохромное) и целевой хронометраж ~6 с:

| Фаза | В видео | В интро |
|---|---|---|
| «ModernSI» проявляется | 0–0,75 с | 0–0,5 с |
| Удержание | 0,75–2,5 с | 0,5–1,3 с |
| Буквы съезжаются к центру с наложением | 2,5–4,0 с | 1,3–2,5 с |
| Пульсирующая точка | 4,0–5,75 с | 2,5–3,3 с |
| Взрыв изогнутых световых нитей | 5,75–6,5 с | 3,3–3,9 с |
| «Welcome!» проявляется, нити разлетаются | 6,75–7,25 с | 3,9–4,5 с |
| Удержание «Welcome!» | 8–10 с | 4,5–5,3 с |
| Оверлей растворяется, сайт проявляется | — | 5,3–6,0 с |

**Реализация**
- Оверлей `position: fixed`, фон глубокий индиго (`--ink`) с радиальным свечением.
- Буквы — DOM-спаны, анимация GSAP timeline.
- Нити — Canvas 2D: 14–18 кривых Безье от центра, каждая нить своего цвета (сирень, небо, мята, орхидея), композиция `lighter`, размытие свечения через `shadowBlur`, затухание хвоста. Учитывается `devicePixelRatio`.
- Шрифт интро — Manrope, как на сайте.

**Поведение**
- Показывается один раз за сессию браузера: флаг в `sessionStorage`, обёрнут в try/catch. Если хранилище недоступно, интро просто показывается.
- Кнопка «Skip» в углу. Клик в любом месте и Esc тоже пропускают интро.
- При `prefers-reduced-motion: reduce` вместо анимации — проявление «ModernSI» и растворение за 0,6 с.
- Звука нет.
- Страница под оверлеем уже отрендерена на сервере: интро не задерживает контент для поисковиков и не влияет на LCP основного контента.
- Пока интро идёт, у `body` стоит `overflow: hidden`, а фокус удерживается на кнопке Skip.

- **Шрифт:** Manrope (variable, self-host через `next/font`), веса 400–800.

До полной вёрстки — макет главной с интро в обеих темах. Его утверждает пользователь.

## 9. Ошибки и устойчивость

- Ошибки API отдаются в едином формате `{"error": {"code": "...", "message": "..."}}`. Коды стабильны, фронтенд опирается на них, а не на текст.
- Валидация — Pydantic, ответ `422` с перечнем полей.
- **Деградация при недоступности хранилищ:**

  | Хранилище | Поведение |
  |---|---|
  | Postgres | Сервис недоступен, `503` |
  | Redis | Вход и авторизованные действия отдают `503`. Публичное чтение работает |
  | MongoDB | Профили отдаются без расширенных полей, редактирование профиля `503` |
  | ClickHouse | Лента и счётчики скрываются на главной, всё остальное работает, outbox копит события |
- Фронтенд: у каждой страницы `error.tsx` с понятным текстом и кнопкой повтора, `not-found.tsx` для 404.
- Markdown рендерится на сервере в безопасный HTML: `markdown-it` с отключённым сырым HTML, ссылки получают `rel="nofollow ugc noopener"`.

## 10. Тестирование

- **Бэкенд — pytest на настоящих базах** из `infra/docker-compose.test.yml`, без моков хранилищ. Почта ловится Mailpit, тесты читают письма через его API.
- **Обязательные сценарии:**
  - регистрация с разрешённым и запрещённым доменом;
  - подтверждение кода, лимит попыток, истечение кода;
  - вход, выход, выход везде, сброс пароля;
  - проверка Origin, rate-limit;
  - все переходы цикла идеи, включая гонку: 2 параллельных голоса на пороге дают ровно один переход в `in_review`;
  - запрет голоса за свою идею;
  - выход автора из команды запрещён;
  - доставка outbox → ClickHouse и повтор после падения ClickHouse;
  - скрытая идея отдаёт 404 посторонним.
- **Фронтенд — Playwright e2e:**
  - интро проигрывается, Skip работает, при повторном заходе в той же сессии интро нет, reduced-motion;
  - путь регистрация → подтверждение → идея → голоса от других пользователей (через API-фикстуры) → рассмотрение → команда → событие → событие видно на главной;
  - все ссылки шапки, футера и главной отвечают 200;
  - нет горизонтального скролла на 360 px.
- **Аудит перед сдачей этапа:**
  - нет `href="#"` и пустых ссылок;
  - нет слов-заглушек;
  - нет названий и цветов университета (grep по исходникам и проверка палитры);
  - контраст токенов ≥ 4,5:1.
